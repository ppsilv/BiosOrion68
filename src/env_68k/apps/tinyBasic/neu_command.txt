## 2. Adicionar no `enum`, na mesma posição relativa

```c
enum {
  KW_LIST = 0,
  KW_LOAD, KW_NEW, KW_RUN, KW_SAVE,
  KW_NEXT, KW_LET, KW_IF,
  KW_GOTO, KW_GOSUB, KW_RETURN,
  KW_REM,
  KW_FOR,
  KW_INPUT, KW_PRINT,
  KW_POKE,
  KW_STOP, KW_BYE,
  KW_FILES,
  KW_MEM,
  KW_QMARK, KW_QUOTE,
  KW_AWRITE, KW_DWRITE,
  KW_DELAY,
  KW_END,
  KW_RSEED,
  KW_CHAIN,
  KW_WHILE,
  KW_WEND,
  KW_HEX,
  KW_HEXPEEK,
  KW_CLS,        /* <--- ADICIONE AQUI, na mesma ordem da tabela acima */
  KW_DEFAULT
};
```

**Importante**: a posição no `enum` precisa bater exatamente com a posição na tabela `keywords[]` — é assim que `scantable()` traduz "achei a keyword na posição N" pra "isso é `KW_CLS`". Por isso adicionei os dois no mesmo lugar relativo (logo antes de `KW_DEFAULT`).

## 3. Adicionar o `case` no dispatch principal

```c
  case KW_HEXPEEK:
    { ... }
    break;
  case KW_CLS:         //  ✔️
    goto cls;
  case KW_DEFAULT:
    goto assignment;
```

## 4. Adicionar o label e a implementação

Junto dos outros labels (`mem:`, `list:`, etc.):

```c
cls:
  clrscr();
  goto run_next_statement;
```

## Por que `run_next_statement`, não `prompt`

Segue o mesmo padrão de `mem:` — assim `CLS` funciona tanto **digitado direto** (modo imediato) quanto **dentro de um programa** (ex: `10 CLS` seguido de mais linhas), permitindo continuar executando o resto do programa depois de limpar a tela. Se fosse `goto prompt`, `CLS` só funcionaria em modo direto e sempre voltaria pro prompt, interrompendo qualquer programa em execução.
